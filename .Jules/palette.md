## 2024-05-18 - MagneticButton accessibility
**Learning:** Found an accessibility issue pattern in MagneticButton where nested interactive HTML elements like an <a> tag inside a <button> can happen if not used correctly, and Framer Motion wrappers can obscure native browser focus outlines. Moreover, we have 'href.startsWith("http")' check which misses uppercase protocols or protocol-relative URLs. Also, wrapping the motion div inside a or button can cause accessibility issues.
**Action:** Always include explicit Tailwind focus-visible utility classes (e.g., focus-visible:ring-2) to ensure keyboard accessibility. Also, build custom wrapper components that handle navigation or actions to avoid rendering nested interactive HTML elements. Pass routing props (like href) to the root wrapper so it conditionally renders as an <a> tag directly, using <span> for styling its children. Use robust regex for target='_blank' checks.
