## 2024-05-15 - Interactive Element Nesting and Focus States
**Learning:** Animated wrapper components (like `MagneticButton`) that conditionally render generic containers (`motion.div`) can obscure native browser focus outlines. Furthermore, if these wrapper components receive child elements that are also interactive (like `<a>`), it creates invalid HTML nesting (e.g. `<a>` inside `<button>`), breaking screen reader semantics and keyboard navigation.
**Action:** When building interactive wrapper components, pass routing/action props directly to the wrapper so it can render the correct root element natively (`<a>` or `<button>`) rather than wrapping nested interactive elements. Always explicitly add `focus-visible` utility classes to these root elements to ensure keyboard accessibility remains intact despite custom animation structures.
