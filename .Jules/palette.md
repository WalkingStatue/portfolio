## 2026-09-03 - Avoid Nested Interactive Elements in Animation Wrappers
**Learning:** When building custom interactive wrapper components (like `MagneticButton` powered by Framer Motion), rendering nested interactive HTML elements like `<a>` inside a `<button>` or another `<a>` creates an invalid DOM structure and breaks accessibility. Additionally, animation wrappers can obscure native browser focus outlines, leaving keyboard navigation without visual feedback.
**Action:** Pass routing props (like `href`) directly to the root wrapper component so it conditionally renders as the appropriate semantic tag (e.g., `<motion.a>` or `<motion.button>`). Use `<span>` for styling its children. Always add explicit `focus-visible` utility classes to these root interactive tags to ensure keyboard accessibility.
